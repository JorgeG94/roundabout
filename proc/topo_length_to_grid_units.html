topo_length_to_grid_units

public pure function topo_length_to_grid_units(length_m, geographic, rad_earth) result(len_grid)

Convert a metres length scale (slope_scale / half_width) into the GRID coordinate units the formula bathymetry setters operate in. Cartesian grids carry positions in metres, so the scale passes through unchanged. Spherical / supergrid / tripolar grids carry positions in DEGREES, so the metres scale is converted to degrees of latitude (meridional metres-per-degree = rad_earth · π/180). This keeps the seamount/spoon length scale commensurate with the grid coordinate; without it a metres scale divided by a degrees position underflows the Gaussian/exponential and the basin collapses flat. Zonal cells are narrower by cos(lat), so a degree-isotropic bump is mildly elongated zonally in physical space — acceptable for these idealised topographies; the degeneracy is what this fixes.

geographic is grid_config_is_geographic(grid_config). The grid kind is passed as a logical, not as the grid_config string: nvfortran 26.9 drops the hidden length of a character(len=*) dummy sitting between two other arguments on the first such call in a routine, and the trim then reads a garbage length and segfaults (#203). Keep character dummies out of this signature.

   pure function topo_length_to_grid_units(length_m, geographic, rad_earth) result(len_grid)
      !! Convert a metres length scale (`slope_scale` / `half_width`) into the
      !! GRID coordinate units the formula bathymetry setters operate in.
      !! Cartesian grids carry positions in metres, so the scale passes
      !! through unchanged.  Spherical / supergrid / tripolar grids carry
      !! positions in DEGREES, so the metres scale is converted to degrees of
      !! latitude (meridional metres-per-degree = `rad_earth · π/180`).  This
      !! keeps the seamount/spoon length scale commensurate with the grid
      !! coordinate; without it a metres scale divided by a degrees position
      !! underflows the Gaussian/exponential and the basin collapses flat.
      !! Zonal cells are narrower by `cos(lat)`, so a degree-isotropic bump is
      !! mildly elongated zonally in physical space — acceptable for these
      !! idealised topographies; the degeneracy is what this fixes.
      !!
      !! `geographic` is `grid_config_is_geographic(grid_config)`. The grid
      !! kind is passed as a logical, not as the `grid_config` string:
      !! nvfortran 26.9 drops the hidden length of a `character(len=*)` dummy
      !! sitting between two other arguments on the first such call in a
      !! routine, and the `trim` then reads a garbage length and segfaults
      !! (#203). Keep character dummies out of this signature.
      real(wp), intent(in) :: length_m, rad_earth
      logical, intent(in) :: geographic  !! Grid positions are in degrees.
      real(wp) :: len_grid
      if (geographic) then
         len_grid = length_m/(rad_earth*DEG2RAD)
      else
         len_grid = length_m
      end if
   end function topo_length_to_grid_units
