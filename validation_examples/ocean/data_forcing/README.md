# File-backed surface forcing (`&ocean_dataovr_nml`, PR-15)

The MOM6 double-gyre reference with **one** change: the wind is read from a
time-varying NetCDF instead of being generated by the built-in analytic
`wind_config = "2gyre"` formula. Grid, bathymetry, stratification, PGF,
Coriolis, drag, viscosity and vcoord are identical to
`../double_gyre/double_gyre_mom6.nml`, so any difference in the answer is
attributable to the forcing path and nothing else.

## Run it

The forcing file is **not committed** — it is generated data, and the repo
keeps binary blobs out of git. Generate it first, then run from the same
directory (the namelist names `wind.nc` as a bare filename, resolved against
the working directory):

```bash
python3 tools/make_forcing_nc.py wind.nc --nx 44 --ny 40 --nt 2 --steady
./build/rdb validation_examples/ocean/data_forcing/double_gyre_dataovr.nml
```

`tools/make_forcing_nc.py` writes NetCDF-3 classic from the Python standard
library alone — this tree has no `netCDF4`, no `numpy`, no `scipy`, and the
project forbids installing packages.

## What it checks

`--steady` writes the analytic 2gyre profile
`tau0 * (1 - cos(2*pi*(j-0.5)/ny))` at **every** record, so the time
interpolation runs but returns the same field for any weight. The claim is
then falsifiable:

> a run driven from a steady file must reproduce the analytic-wind run.

Measured over 10 days (CPU, gfortran), file-driven vs
`double_gyre_mom6.nml`:

| Day | file-driven `En` | analytic `En` |
|-----|------------------|---------------|
| 1   | 3.036E-03        | 3.036E-03     |
| 5   | 2.738E-03        | 2.738E-03     |
| 10  | 2.241E-03        | 2.241E-03     |

That is the regression case (`double_gyre_dataovr` in
`tests/regression/manifest.py`), which generates the file into its scratch dir
via the manifest's `setup` hook.

## Why not the seasonal mode for the regression

Drop `--steady` and the profile is modulated by `sin(2*pi*t/period)`, which
makes the interpolation visible in the data and reverses the wind halfway
through the cycle. It is the better *demo* — but it is a poor *test*, for a
reason worth recording:

**Over 10 days this configuration is not wind-sensitive.** The double-gyre
spin-up takes hundreds of days; at day 10 the energy is dominated by initial-
condition adjustment. Measured `En` at day 10:

| Wind | `En` day 10 |
|------|-------------|
| analytic 2gyre, steady 0.1 Pa | 2.241E-03 |
| seasonal file, ramping to ~0.04 Pa | 2.212E-03 |
| **no wind at all** | 2.212E-03 |

A seasonal-mode regression case would therefore pass just as happily with the
forcing path completely dead. Holding the forcing values fixed and A/B-ing the
*path* is the only version of this that can fail for the right reason.

(The path is live: a 50x wind gives `En` = 1.125E-02 at day 10 against
2.212E-03. The signal exists, it is just far below the IC adjustment at
realistic amplitude and this horizon.)

For a demo where the time variation *is* visible, run the seasonal file for
O(100) days:

```bash
python3 tools/make_forcing_nc.py wind.nc --nx 44 --ny 40 --nt 4
# then raise t_end in the namelist to ~100 days
```

## File layout: the staggered face counts

The wind file is **C-grid staggered**, so the two components have different
extents and the file carries four horizontal dimensions:

```
double taux(time, y,  xf) ;   x = 44,  xf = 45
double tauy(time, yf, x ) ;   y = 40,  yf = 41
```

An x-face array spans `nx_phys + 1` faces, not `nx_phys`. The trailing face is
**owned by the local rank** under the west/south-owns-the-seam rule, so no halo
exchange can supply it — it has to come from the file. Supplying only `nx_phys`
leaves that face at zero, which halves the cell-centred `stress_mag` in the last
column and hands a zero to the east neighbour's seam. `make_forcing_nc.py`
emits the correct counts; a hand-built file must too.

## Ghost cells are exchanged, never extrapolated

Stress ghosts are filled by `ocean_seam_refresh_surface_stress` — MPI exchange,
then periodic wrap on any axis the exchange did not own, then the tripolar
fold. Nothing extrapolates.

That matters at scale rather than here: at an MPI seam the ghost belongs to the
neighbour rank, and copying the local edge value there gives a
decomposition-dependent answer that no single-rank test can detect. The
thermodynamic flux tags get no ghost treatment at all, deliberately — they are
applied column-locally and never read in a ghost cell.
