Turns the nine-field atm_state_t into the ocean’s own surface forcing slots (ocean_surface_stress_t%tau_x/tau_y, ocean_surface_flux_t’s component set): rotate the prescribed wind onto the model grid axes, form the relative wind against the ocean’s own surface current, run the Large & Yeager bulk-flux column kernel (rdb_ocean_bulk_flux) cell by cell, write the shortwave / longwave / precipitation / pressure-loading components, apply the sea-ice open-water weighting when a sea-ice component is configured, and finish by turning the cell-centred stress into the C-grid face pair.

No ice seam here. The atmosphere -> sea-ice forcing dispatcher (ice_atm_forcing_from_atm) is a separate chunk (C2c-3b); this module only READS the sea-ice state’s already-live part_size category array to scale the ocean’s own open-water fraction – it never writes into ocean_sea_ice_t.

Why the bespoke per-cell kernel instead of calling bulk_flux_driver_2d over the whole (nx_total, ny_total) tile. atm_state_t’s own docstring is explicit: every field array is ghosted but only the PHYSICAL interior is ever written – “no consumer in this chunk reads a ghost cell” – so a ghost cell’s tas/huss/psl sits at its source=0.0_wp allocation value forever. Calling the bulk-flux column kernel there would divide by t_air = 0 (rho_air = slp/(R*t_air*(...))) and most namelists this provider is gated on (grid_config must be spherical/supergrid/tripolar, and a tripolar cap REQUIRES periodic east/west) have genuinely WET ghost cells, so this is not a hypothetical edge case. bulk_forcing_core_impl below loops the physical interior only (the ii = nghost + i offset idiom rdb_atm_state’s own atm_state_scatter_impl uses) and calls bulk_flux_column – the same per-column kernel bulk_flux_driver_2d itself calls – directly, so every physical cell’s q_sens/q_lat/evap/stress is bit-for-bit what a direct bulk_flux_column call produces (what the C2c tests assert). Ghost cells of every output are intentionally left UNTOUCHED by this kernel, matching rdb_ocean_data_forcing’s “ghosts are EXCHANGED, never extrapolated” contract; the stress pair’s ghosts are filled afterwards, see below.

Stress: cell-centred, then a scalar halo copy, then the face average, then the REAL vector seam refresh. bulk_flux_column naturally produces a CELL-CENTRED stress (same point as uas/ vas). Averaging that onto the C-grid tau_x/tau_y FACES needs the neighbour cell on both sides of every face, including the faces at the tile edge – which needs this rank’s cell-centred ghost ring to hold the NEIGHBOUR’s real physical value, not a locally-recomputed (zero-atm-input) one. ocean_halo_centre (the 2D specific) supplies exactly that: an MPI exchange (or local periodic wrap) of the plain SCALAR field, no vector sign handling – which is why the tripolar fold row comes out of it with the wrong sign (a scalar copy, not a vector one) and is deliberately not relied on: ocean_seam_refresh_surface_stress, called last, re-does the face pair’s own proper vector exchange + periodic wrap + fold and is what leaves tau_x/tau_y (and stress_mag) correct everywhere a kernel reads them.

Open-water weighting. ocean_sea_ice_t%part_size(:,:,0) IS the open-water fraction already – the category partition sums to 1 by construction (part_size(:,:,0) = 1 - conc at the ITD seed, rdb_ice_init), so 1 - Sum_{c=1}^{ncat} part_size(c) and part_size(0) are the same number; this module reads the field directly rather than re-summing it. this%open_water is seeded to 1 at configure and is the array bulk_forcing_core_impl always multiplies by; it is refreshed from ice%part_size(:,:,0) only when ice%enable, so a run with no sea-ice component never touches an ocean_sea_ice_t array (CLAUDE.md’s “a host-gated call that hands a state array to an external subroutine still costs” – here the guard is at the CALL SITE, so the array is never even named when ice is off).

Component ownership. Every field this module writes is a PR-12 component (q_sens, q_lat, q_sw, q_lw, evap, lprec, fprec, p_surf_atm) – never Q_heat/Q_salt directly (ocean_surface_flux_assemble rebuilds those every thermo step). lprec/fprec are mass-flux components carrying enthalpy, so this module also fills their heat_content_<flux> companions – isothermal at the ocean’s own SST, the convention rdb_ocean_surface_flux’s own component contract and tests/test_ocean_surface_forcing_type.F90 already use (“rain at T_s”). No salt component is written (v1 bulk fluxes carry no virtual-salt term), so has_salt is left untouched.

Derived Types

type, public ::  bulk_forcing_t

Persistent per-step scratch for the ocean bulk-flux consumer. taux_c/tauy_c MUST be module-/state-level (never a local automatic array inside bulk_forcing_apply): they are written by bulk_forcing_core_impl, then mutated IN PLACE by the halo exchange, then read by the face-average kernel – three separate calls sharing one buffer every step, and a per-step local-allocate of a (nx_total,ny_total) array stalls the device on entry/exit (CLAUDE.md “Persistent kernel workspaces”).

private pure subroutine bulk_forcing_core_impl(nx, ny, ng, nxp, nyp, nz, n_iter, wind_relative, ocean_albedo, z_wind, z_ta, emissivity, wet_T, angle_dx, uas, vas, tas, huss, psl, rlds, rsds, prra, prsn, u_face_x_layer, v_face_y_layer, hTr_T, h_layer, open_water, taux_c, tauy_c, q_sens, q_lat, evap, q_sw, q_lw, lprec, fprec, p_surf_atm, heat_content_lprec, heat_content_fprec)

One bulk_flux_column call per PHYSICAL T-cell (see the module docstring for why ghost cells are never touched here). Land / dry cells (wet_T <= 0.5) write explicit zero to every output, matching bulk_flux_driver_2d’s own NaN-safe if convention (a multiply by a zero mask would not scrub a NaN land input). Explicit-shape throughout, integer dims first.

private pure subroutine bulk_forcing_stress_face_impl(nx, ny, taux_c, tauy_c, tau_x, tau_y)

Cell-centred stress -> C-grid face average, ALL faces (interior and the two tile-edge faces per axis), inverting ocean_surfstress_derived_impl’s own face -> centre average (rdb_ocean_surface_stress) so the two are each other’s round-trip on a uniform field. Edge faces (i=1/nx+1, j=1/ny+1) are one-sided (only one neighbouring cell exists in the array) – excluded from the interior loop by RANGE, per CLAUDE.md’s vectoriser-edge-bug rule, never by an in-loop i==1 .or. i==nx+1 guard.
