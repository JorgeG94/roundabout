Builds the nine-field atmospheric state tas, huss, uas, vas, psl, rlds, rsds, prra, prsn (Tsujino et al. 2018, JRA55-do) on the model T-grid: time-blend each field’s current bracket on the shared PR-14 reader into a reusable longitude-circle x latitude-band WINDOW buffer, then regrid that window onto the physical interior with the in-model lat-lon weights (rdb_regrid_latlon, Jones 1999). No MPI communication in the provider itself — every rank reads its own hyperslab (the reader’s win_i0/win_j0/win_nx/win_ny override, C2c-1) and regrids independently.

rsds – held interval + diurnal cosine-zenith factor (sw_interp = "coszen", the namelist default, C2c-2b). The JRA55- do rsds file carries 3-hour interval MEANS; registering it with hold = .true. and t_offset = sw_offset_s (default -5400 s, half the 3-hour bucket) makes the shared reader return that bucket’s value PIECEWISE-CONSTANT (rsds_rec, weight forced to 0 – no blend toward the next record) rather than linearly interpolated. The diurnal shape within the bucket is restored by rsds = rsds_rec * cosz / cosz_mean (0 where cosz_mean < 1e-6, i.e. the whole bucket is night): cosz is the INSTANTANEOUS cosine of the solar zenith angle at the query time t; cosz_mean is a 12-point midpoint quadrature of max(0, cos Z) over the bucket [t_rec, t_rec + 3h) that rsds_rec itself represents (t_rec = floor(t / 3h) * 3h, the JRA55-do bucket boundary) – so cosz_mean * 3h is (to the quadrature’s own accuracy) the bucket’s true clear-sky-insolation-weighted mean, matching the file’s interval-mean convention and preserving the daily energy total exactly in the limit where the model’s own step cadence samples the same 12 nodes (test_ocean_atm_state’s energy-identity gate). The solar position (declination + equation of time) comes from the Spencer (1971) Fourier fit – a day-of-year + hour-of-day function only, computed HOST-SIDE via rdb_calendar (calendar arithmetic is not device-safe) and handed to the per-cell device kernel as a handful of scalars/short arrays; the kernel itself does only elementwise trigonometry on geolonT/geolatT, never touches the calendar. orb_year is the reserved Berger (1978) orbital- parameter follow-up – validate_config refuses any value other than its default, since this chunk’s declination uses the FIXED Spencer coefficients. sw_interp = "linear" disables all of the above (hold = .false., t_offset = 0, plain blend, same answer as every other flux) – rsds is then rsds_rec copied straight through.

There is NO bulk-flux/ice-seam CONSUMER here (that is C2c-3) – the engine only configures this slot and refreshes it every step; nothing reads tas/huss/… yet.

Two reusable window buffers, not one per field. win_bl/win_cv are each sized to ONE weight set’s source footprint (regrid_window) and reused by every field that uses that weight set: tas, huss, uas, vas, psl always use the bilinear set (wb, &ocean_atm_forcing_nml states_regrid has no other legal value); rlds, rsds, prra, prsn use wb or the conservative set (wc) together, selected once at configure by fluxes_regrid. Both weight sets are always built (bit-identical either way the knob is set) – only the per-field BINDING differs. Each field’s call sequence is blend-into-window, regrid-into-a-physical-size scratch (tgt_bl/tgt_cv, a persistent workspace – never a per-step local-allocate, CLAUDE.md “Persistent kernel workspaces”), then scatter that scratch into the field’s own ghosted array at the nghost offset – so the window/scratch buffers are safely reused read-after-write within one field’s update, before the next field overwrites them.

Ghosts are untouched. Every field array is (nx_total, ny_total) but only the physical interior is written here – no consumer in this chunk reads a ghost cell, and extrapolating into one is the data-forcing anti-pattern rdb_ocean_data_forcing’s docstring already warns against.

public subroutine atm_state_update(this, reader, metrics, t)

Blend + regrid every one of the nine fields’ current bracket, then (sw_interp = "coszen") restore rsds’s diurnal shape from the held bucket mean – see the module docstring’s rsds paragraph. t must be the same model time ocean_data_input_update_all was just called with – the reader enforces this and aborts otherwise (see ocean_data_input_update_2d’s fail-loud freshness check). metrics supplies geolonT/geolatT for the coszen kernel (unused, and not read, when sw_interp = "linear").

private pure subroutine atm_coszen_apply_impl(nx_total, ny_total, nghost, nx_phys, ny_phys, nq, hour_frac_q, decl_q, eqtime_q, hour_frac_inst, decl_inst, eqtime_inst, geolonT, geolatT, rsds_rec, cosz, cosz_mean, rsds)

The ONE device kernel: per physical T-cell, the instantaneous cos Z (clamped >= 0) at (hour_frac_inst, decl_inst, eqtime_inst), the nq-point midpoint-quadrature mean of max(0, cos Z) over the (hour_frac_q, decl_q, eqtime_q) nodes, and the coszen-restored rsds. Explicit-shape throughout; no cross-module calls – every quantity but geolonT/geolatT is a host-precomputed scalar/short array (CLAUDE.md do-concurrent dummy + device-safety rules).
