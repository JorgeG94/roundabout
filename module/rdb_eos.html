Holds the EOS variant tag + scalar EOS coefficients (linear Boussinesq) and the kernels that convert (T, S) -> ρ on the multilayer C-grid. Coastal uses a sibling linear EOS in rdb_ml_eos; the ocean path needs a real nonlinear EOS along the FV pressure-gradient integration path. Default is Wright (1997) — the same EOS MOM6 uses by default — chosen for cost (one rational expression, no LUT) and accuracy in the open ocean. TEOS-10 is a future option.

Phase 5c status: linear branch live; Wright + LUT scratch still pending. The kernel follows the outer-shim + flat-impl pattern: an outer shim pulls the registered S, T tracer arrays off the owning state and forwards them as bare 3D arrays to the inner _impl routine. This avoids the NVHPC stdpar deep-deref issue with array-of-derived-types tracer registries (see CLAUDE.md feedback_nvhpc_impl_inlining). This module is regime-agnostic — it carries NO ocean-state dependency; the ocean C-grid shim ocean_eos_compute lives in rdb_ocean_eos_compute (core/ocean/state/), and the coastal shim in rdb_ml_eos.

Translate a &ocean_eos_nml tfreeze_set=... string into a TFREEZE_SET_* code.
